# Plex native TrueNAS migration candidate

This is a reviewed candidate, not authorization or a deployment. Keep the legacy Servarr LXC stopped and intact. Owner located its original configuration (about 3.1 GiB), including primary Plex library and blobs databases and scheduled historical copies. Original Docker image labels report 1.43.5.11079-b3b13e506; the owner recovered the registry digest pinned in Compose. Image ID is not a registry digest. Verify the pinned pull matches the expected image/version before starting. Do not combine migration and an upgrade.

## Recovery and cutover gates

- Copy the entire stopped source config, retaining numeric ownership, modes, ACLs, xattrs, links, and SQLite WAL/SHM files if present. Use a private authenticated transfer, never the public repo or shared media export. Validate the copy against source, and preserve original bytes independently. Treat Preferences.xml and all configs as secrets.
- Create the exact native appdata/plex dataset through an authorized path; use a private POSIX permissions layout. Check effective read/write for UID/GID 1000 on config and read access for media. Do not recursively change the existing media dataset or allow Plex to rewrite ownership. The official image uses PLEX_UID and PLEX_GID rather than PUID/PGID.
- On an isolated working copy use the pinned image's own Plex SQLite interpreter to run PRAGMA integrity_check on both current databases. Never run repair against the original. Preserve any required SQLite sidecars. Verify all config files copied and a consistent independent replica exists before first startup.
- Check actual host TCP/UDP port conflicts, the local Intel /dev/dri device nodes and effective permissions. PR #29 verified both media directory paths, the reported Intel GPU choice and no app reservation of 32400 via live MCP. This does not prove all host ports free or hardware transcoding.
- Host networking preserves original deployment behavior, but binds listeners on host interfaces; restrict access via LAN/tailnet and review existing firewall/remote-access settings. Do not enable public ingress or unauthenticated networks. Retain the existing server identity; do not supply a new claim token.
- Initial movie and TV mounts are read-only with original in-container paths. Use an ephemeral 4 GiB capped tmpfs for /transcode as a starting choice; monitor memory and transcode capacity. No privileged container or Docker socket. The official image needs its normal initialization behavior. Confirm GPU group access; do not grant world-writable device permissions.
- Use TrueNAS native app lifecycle only after a fixed approved definition, preflight and explicit cutover approval. Verify Plex login and existing library/watch history, playback, and a deliberately forced transcode marked (hw) if Plex Pass/hardware acceleration is available. Roll back by stopping the new app and preserving its data; never run both instances with the same identity. No automatic deletion or data rollback.

Sources: official image README https://github.com/plexinc/pms-docker and Plex SQLite procedure https://support.plex.tv/articles/repair-a-corrupted-database/ . No live Plex deployment has been performed.
